# АНАЛИТИКА ПРОЕКТА: «Мультархив» — интерактивная энциклопедия классической анимации

Автор: Гаврилов Н.С.

## 1. ЧТО ЭТО И ЗАЧЕМ (СУТЬ)

**Что делаем:** десктопное (Electron, Windows и Linux) и Android-приложение «Мультархив» — интерактивную энциклопедию классической анимации. В основе советская мультипликация, рядом с ней мировая классика (Disney, Fleischer, Hanna-Barbera, Pixar, Toei и другие). Внутри каталог с поиском и фильтрами, страницы мультфильмов, персон и студий, интерактивная хронология истории анимации, избранное и работа без сети.

**Зачем:** собрать разрозненные сведения о классической анимации в одном месте. Пользователь находит мультфильм по названию (в том числе оригинальному), году, стране, студии, жанру, технике или создателю и переходит по ссылкам к связанным фильмам, людям, студиям и событиям истории анимации.

## 2. ДЛЯ КОГО (ЦЕЛЕВАЯ АУДИТОРИЯ)

**Основные пользователи** (оценка, не измерение):

- Зрители, которые ищут мультфильм из детства по смутным воспоминаниям.
- Ценители и коллекционеры классической и ретро-анимации.
- Студенты и исследователи кино и анимации.

**Их главная задача в приложении:** быстро найти мультфильм и открыть его страницу с постером, кадрами, историей создания и составом создателей. Затем перейти к другим работам тех же людей или студии и увидеть место фильма в истории анимации.

## 3. НА ЧЁМ ДЕЛАЕМ (СТЕК)

- **Клиент:** один общий интерфейс (SPA) на React 18 и Bootstrap 5, сборка Vite. Слой данных с офлайн-кешем в IndexedDB общий для десктопа и Android.
- **Десктоп:** Electron (`contextIsolation`, без `nodeIntegration`, `sandbox`), сборка через electron-builder: переносной exe для Windows, AppImage для Linux.
- **Android:** Capacitor, debug APK. iOS не требуется.
- **Сервер:** Python/Django + Django REST Framework, Pillow для превью (WebP 480 и 1600 px), django-cors-headers, раздача медиа с поддержкой HTTP Range.
- **База данных:** SQLite.
- **Внешние источники:** тексты, постеры, кадры и логотипы студий взяты из Википедии и Wikimedia Commons, источник и автор каждого изображения хранятся в данных. Видео: кнопка «Смотреть» ведёт на поиск по официальному YouTube-каналу «Союзмультфильма». Для прямого файла есть встроенный плеер. Платежей, push-уведомлений и мониторинга нет.
- **Сеть:** сервер работает на компьютере в локальной сети. Адрес сервера фиксируется при сборке приложений и пользователю недоступен.
- **Репозиторий:** монорепо `server/`, `desktop/`, `client/`, собранное из двух отдельных заготовок (Django_template_web_api_basic и electron_desctop_mobile_template). Сборка exe и apk идёт через GitHub Actions, готовые файлы публикуются в релизах.

## 4. ЧТО СОЗДАЁМ (КОМПОНЕНТЫ ПРИЛОЖЕНИЯ)

**Роли пользователей:**

- Обычный пользователь (без регистрации).
- Администратор или редактор контента (наполнение каталога, изображений и событий хронологии через админку Django).

**Основные экраны и модули:**

1. **Каталог:** сетка или список карточек (постер, название, оригинальное название, год, страна, студия, длительность, техника). Карточки реагируют на наведение кнопкой «Подробнее», избранное ставится прямо с карточки. «Загрузить ещё» и автоподгрузка при прокрутке, «Случайный мультфильм».
2. **Поиск и фильтры:**
   - глобальный поиск в верхней панели (Ctrl+K) с подсказками по мультфильмам, студиям и создателям;
   - в каталоге — живой поиск, годы «от–до», страна, студия, жанр, техника анимации и сортировка;
   - активные фильтры показаны снимаемыми метками.
3. **Страница мультфильма:** постер и метаданные, хлебные крошки, разделы «О мультфильме», «История создания», «Создатели» (с озвучанием), «Галерея» с полноэкранным просмотром, «Интересные факты» (с наградами), серия и «Похожие мультфильмы».
4. **Страницы студий и персон:**
   - справочник студий: поиск, страна, период работы, сортировка;
   - страница студии: история, ключевые создатели, важные вехи, фильмы по десятилетиям и хронология работ;
   - страница персоны: работы по ролям.
5. **Хронология истории анимации:** эпохи от «До 1930-х» до «1990-е и позже» и фильтры по стране, студии, технике и типу событий. Ключевые вехи выделены. По клику на событие или мультфильм открывается панель подробностей со ссылками.
6. **Личное:**
   - избранное: счётчик, сетка или список, сортировка, быстрые фильтры, удаление с «Вернуть», очистка с подтверждением;
   - отметка «Просмотрено»;
   - светлая и тёмная тема;
   - сворачиваемое боковое меню (кнопка или Ctrl+B).
7. **Офлайн-режим:** кеш последних ответов сервера (до 300) и изображений (до 500). Ранее открытые страницы работают без сети с пометкой о сохранённых данных.
8. **Видео:** кнопка «Смотреть» с внешней ссылкой или встроенный HTML5-плеер.
9. **Настройки:** тема, состояние подключения к серверу (адрес только для чтения), очистка сохранённых данных.

Функции и дизайн одинаковы на десктопе и телефоне. На узком экране боковое меню становится полосой иконок и раскрывается поверх контента.

**Ключевые сущности (данные):**

- Мультфильм (название, оригинальное название, год, длительность, аннотация, «О мультфильме», «История создания», «Интересные факты»)
- Студия (страна, город, годы работы, история, логотип)
- Страна
- Персона
- Участие (роль: режиссёр, сценарист, композитор, художник, озвучание; персонаж)
- Жанр, техника анимации или тег
- Награда
- Изображение (постер, кадры; источник, автор, лицензия)
- Серия и связи между фильмами
- Событие истории анимации (веха, технология, студия, премьера, награда)
- Видео-источник (внешняя ссылка или файл)

**Демо-данные:** 42 мультфильма, 12 студий, 97 персон, 16 событий истории анимации, около 80 изображений.

**Локальные данные клиента:** избранное, «просмотрено», тема, состояние бокового меню, кеш.

## 5. КАК ЗАПУСКАЕТСЯ И СОБИРАЕТСЯ

- **Сервер:** `./serve.fish` на компьютере с проектом. При первом запуске создаёт окружение, применяет миграции и загружает демо-данные. Затем открывает порт 8000 в ufw на время работы. Отдельный процесс-сторож закрывает порт при любой остановке (Ctrl+C, `./serve.fish stop`, падение сервера).
- **Приложения:** GitHub Actions собирает exe (Windows) и apk (Android) при каждом изменении `main`. Адрес сервера берётся из переменной репозитория `API_BASE`. Готовые файлы публикуются в релизах.
- **Подключение:** устройства с приложением должны быть в той же локальной сети, что и сервер.
